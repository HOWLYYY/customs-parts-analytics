# Customs parts analytics

October 2026 portfolio extension of a private customs parts catalog. This repository contains the read-only analytics, a deterministic synthetic catalog, and a Power BI project. It does not contain production workbooks, the production database, technical documents, invoices, or credentials.

The figures in `demo/synthetic/report` are calculated from that synthetic catalog. They are not historical production results.

## Reproduce

Python 3.11 or newer is enough. The analytics code uses the standard library.

```bash
python3 -m unittest discover -s tests -t .
python3 scripts/build_synthetic_catalog.py
python3 scripts/analyze_catalog.py --demo --out demo/synthetic/report
```

Open `demo/synthetic/report/preview.html` for the portable report. `sample_analysis.md` and `summary.json` in the same folder are written by the same run.

The checked-in preview is regenerated by `scripts/build_synthetic_catalog.py`. Tests compare it with a fresh database built from `analytics/synthetic.py`.

## Metrics

Every measure uses columns that exist on `deliveries`, `parts`, `shipment_lines`, `archive_sources`, and `archive_lines`.

- **Catalog completeness.** Seven key fields: English name, Russian name, graph description, TNVED code, manufacturer, country of origin, and tech-doc path. A text field counts as filled only when it is not blank. Average completeness is filled fields divided by parts times 7.
- **Shipment composition.** Lines, distinct articles, quantity, net weight, gross weight, and declared batch value per delivery. Declared batch value is the sum of `batch_price_rub`. Blank amounts stay out of the sum. This is not revenue, margin, or stock turnover.
- **Repeat and new articles.** Deliveries are ordered by `imported_at`, then id. An article is new in the delivery where it first appears and a repeat in later deliveries. Its introduction line is the earliest shipment line in that same order. The sum of new appearances equals the number of distinct shipped articles.
- **Missing descriptions and documents.** Blank names, graph descriptions, and TNVED codes are counted on parts and on shipment lines. A missing tech doc is a blank `tech_doc_path`. A filename without a path is a filled `tech_doc_filename` with a blank path. Archive-only parts appear in `archive_lines` and on no shipment line.
- **Price and weight consistency.** A price check runs only when quantity, unit price, and batch price are all present. It mismatches when the gap is greater than `max(0.05, 0.5% of the batch price)`. Net and gross weight checks use the same rule with `max(0.001, 0.5% of the total weight)`, and only when quantity, unit weight, and total weight are all present. Missing gross weight is not itself an issue, because shipment workbooks often leave it empty. Gross below net is reported when both totals are present and gross is lower than net.

The synthetic demo is built so these rules can be checked by hand: 10 shipment lines, declared batch value 2,330.00, one price mismatch, one net-weight mismatch, one gross-weight mismatch, and one gross-below-net line. Eighteen reconciliations in the report must pass before a file is written.

`scripts/analyze_catalog.py` can also read another SQLite catalog with `--db`, using a read-only connection. Do not publish that output. The command refuses to write a non-synthetic catalog into `demo/synthetic` or `powerbi`.

## Power BI

Open `powerbi/CustomsPartsAnalytics.pbip` in Power BI Desktop on Windows. Set the `DataRoot` parameter to the absolute path of `demo/synthetic/report`, then refresh. Standalone M scripts for the same queries are in `powerquery/`. DAX measures live on the `_Measures` table and are copied in `powerbi/measures.dax`.

The project uses the formats documented by Microsoft and checked against the published JSON schemas on 28 October 2026:

| File | Schema / version |
| --- | --- |
| `CustomsPartsAnalytics.pbip` | PBIP shortcut 1.0.0, version 1.0 |
| `definition.pbism` | Semantic model definitionProperties 1.0.0, version 4.0, TMDL folder |
| `definition.pbir` | Report definitionProperties 2.0.0, version 4.0, PBIR folder |
| `definition/report.json` | PBIR report 3.3.0 |
| `page.json` | PBIR page 2.1.0 |
| `visual.json` | PBIR visual container 2.13.0 |
| `definition/*.tmdl` | TMDL, compatibility level 1567 |

Those JSON files were validated locally against the schemas in [microsoft/json-schemas](https://github.com/microsoft/json-schemas). There is no `.pbix` file. Microsoft documents that converting between PBIX and PBIP requires Power BI Desktop, and Power BI Desktop was not installed on the macOS machine that prepared this project. Desktop was therefore not used to refresh the model or to execute the DAX. The Python tests instead reconcile the exported columns that those DAX measures sum. Opening the project may prompt Desktop to normalize line endings or to raise a schema version; that rewrite has not been captured here.

The model imports CSV with Power Query. Cards, a shipment table, a value chart, and a data-quality page are stored as PBIR visuals bound to those measures and columns.

## Layout

```text
analytics/          metric calculations, CSV/HTML export, PBIP writer
demo/synthetic/     synthetic SQLite database and generated report
powerbi/            PBIP, TMDL semantic model, PBIR report
powerquery/         the same M queries as standalone scripts
scripts/            build_synthetic_catalog.py and analyze_catalog.py
sql/schema.sql      catalog tables the synthetic database is built from
tests/              hand-checked expectations and reconciliations
```

The private catalog application that imports Excel deliveries and serves the parts website is not part of this repository.
